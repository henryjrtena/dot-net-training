Swagger for API Testing

Lesson Objective

Document and test your Todo List API with Swagger so you can try the todo endpoints before connecting the frontend.

Install package

dotnet add package Swashbuckle.AspNetCore

Complete Program.cs

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

var app = builder.Build();

if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}

app.UseHttpsRedirection();
app.UseAuthorization();
app.MapControllers();

app.Run();

Test endpoints

Run API and open /swagger. Validate GET/POST/PUT/DELETE and auth headers.

dotnet run --project TodoList.Api

Nice to Know Before Moving On

Common mistakes

Swagger may load, but the API can still fail if routes, models, or package restore are not correct.

How C# maps to ASP.NET Core

Swagger reads endpoint metadata and gives you a quick browser UI for testing without writing a frontend first.

Helpful habits and style tips

Use Swagger early in development to validate payloads and status codes before debugging browser code.
